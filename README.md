# DSH 产品结构与开发顺序

这份文档整理的是 DSH 桌面端的产品分层、横向能力、领域能力、获客渠道和开发顺序。

核心判断很简单：

- **横向能力本身也是产品**
- **领域能力是产品族，不是固定单品**
- **开发顺序要先横向、后领域**
- **开发者 Agent 不纳入当前范围**
- **连接器 / MCP 属于 DSH 底座能力，不单列产品**

## 1. 总体分层

| 层级 | 内容 | 角色 |
| --- | --- | --- |
| 底座层 | DSH 桌面端、证据底座、状态、权限、审计、导出、连接器 / MCP 接入能力 | 所有产品共用 |
| 横向产品层 | 深度调研、数据分析、文档/报告生成、知识库、客服辅助、多模态工作台 | 可单独售卖，也可复用到各领域 |
| 领域产品层 | 专利、招投标、具身智能 | 面向具体行业和场景 |

## 2. 横向产品层

这些不是“配套功能”，而是独立产品。

### 2.1 深度调研

- 多来源检索
- 证据整理
- 来源对比
- 冲突判断
- 研究报告输出

### 2.2 数据分析

- Excel / CSV / 数据库读取
- 清洗和汇总
- 指标计算
- 图表和异常分析
- 周报 / 月报输出

### 2.3 文档 / 报告生成

- Word
- PPT
- Excel
- 研究报告
- 方案草稿

### 2.4 知识库

- 企业文档问答
- 制度检索
- 经验沉淀
- 口径统一

### 2.5 客服辅助

- 回复草稿
- 工单总结
- 知识引用
- 升级建议

### 2.6 多模态工作台

处理多种内容形态：

- 文本
- 图片
- 表格
- PDF
- 音频
- 视频

## 3. 领域产品层

领域产品不是固定数量上限，而是按业务和渠道持续扩展。

### 3.1 专利

- 专利检索
- 同族分析
- 引证分析
- 权利要求对比
- 技术路线梳理

### 3.2 招投标

- 招标监测
- 资格条件分析
- 评分项分析
- 风险提示
- 响应草稿

### 3.3 具身智能

- 论文和专利追踪
- 公司和产品梳理
- 赛道情报
- 项目监测

## 4. 开发顺序

建议按下面顺序推进：

1. **深度调研**
2. **数据分析**
3. **文档 / 报告生成**
4. **知识库**
5. **客服辅助**
6. **多模态工作台**
7. **再逐个补领域产品**

原因：

- 前三项最容易展示 DSH 的核心价值
- 知识库和客服辅助更适合做企业内部协作入口
- 多模态工作台能增强桌面端的通用生产力
- 领域产品适合在底座稳定后分批做

## 5. 获客渠道匹配

| 产品 | 主要客户 | 主要渠道 |
| --- | --- | --- |
| 深度调研 | 企业负责人、咨询、投资、研究人员 | 内容渠道、定向演示、行业合作 |
| 数据分析 | 运营、销售、财务、管理 | 内容案例、企业服务、平台接单 |
| 文档 / 报告生成 | 咨询、销售、投标、研究 | 平台接单、内容营销 |
| 知识库 | 中小企业、研发团队 | 集成商、企微服务商、直销 |
| 客服辅助 | 电商、教育、软件、服务企业 | CRM 厂商、客服外包、企微生态 |
| 多模态工作台 | 文档密集、图片密集、视频密集的团队 | 演示转化、行业合作 |
| 专利 | 研发企业、专利代理、技术转移 | 专利代理机构、园区、技术转移中心 |
| 招投标 | 工程商、软件商、设备商 | 招标代理、行业协会、企业服务商 |
| 具身智能 | 机器人企业、投资机构、产业园 | 展会、产业园、行业媒体 |

## 6. 排除项

- **开发者 Agent 不纳入**
- **连接器 / MCP 不单列产品**
- 不把领域产品和横向产品混成一个大模块
- 旧候选中的国创平台、商品比价/询价、内部经验、电子设计论坛、设计案例、专家资料，不纳入当前版本

## 7. 最终判断

DSH 的正确路径不是先做一个“大而全 AI 产品”，而是：

1. 先把横向产品做成能卖、能演示、能复用的独立产品
2. 再把这些能力沉淀成领域产品族
3. 用渠道去匹配产品，而不是用产品硬找所有渠道
