# DSH 闲鱼商品化项目结构

这份文档说明三件事：

1. 闲鱼前台怎么包装商品
2. DSH desktop 怎么作为统一交付底座
3. 后续目录怎么分层、怎么隔离能力包

核心判断很简单：

- 闲鱼卖的是**商品**
- DSH desktop 提供的是**统一交付**
- 能力包必须**独立目录、独立物料、独立测试、独立发布**
- `连接器 / MCP` 属于底座能力，不单列产品
- `开发者 Agent` 不纳入当前版本

## 1. 项目总结构

| 层级 | 目标 | 产物 |
| --- | --- | --- |
| 闲鱼商品包装层 | 引流、成交、展示 | 商品名、标题、介绍、海报、详情页、FAQ |
| DSH desktop 统一交付层 | 完成交付、演示、复用 | 底座、能力包、导出、权限、审计 |
| 能力包层 | 按问题和场景交付 | 深度调研、数据分析、文档/报告生成、知识库、客服辅助、多模态工作台、专利、招投标、具身智能 |

## 2. 闲鱼商品包装层

闲鱼上架时，不写内部能力名，写的是用户能听懂的结果。

### 2.1 商品命名原则

- 结果先行
- 单点问题
- 交付物明确
- 不写内部术语

### 2.2 标题模板

- `AI深度调研报告｜带引用｜可交付Word/PDF`
- `AI数据分析｜Excel/CSV清洗汇总｜出图表`
- `AI报告/PPT生成｜资料整理成稿`
- `AI知识库搭建｜企业文档问答`
- `AI客服辅助｜回复草稿+知识引用`
- `多模态资料处理｜PDF/图片/表格统一整理`

### 2.3 介绍结构

每个商品介绍都建议包含：

1. 你要解决什么问题
2. 你会收到什么交付
3. 需要你提供什么输入
4. 多久交付
5. 不包含什么
6. 是否支持复核和修改

### 2.4 海报结构

- 封面海报：结果 + 场景 + 交付形式
- 流程海报：输入 -> 处理 -> 输出
- 证据海报：样例截图、报告样例、表格样例

### 2.5 闲鱼上架建议

第一批上架优先用最容易解释、最容易单次成交的商品：

1. 深度调研
2. 数据分析
3. 文档 / 报告生成
4. 多模态资料处理

知识库、客服辅助、专利、招投标、具身智能可以作为后续扩展和更高客单价商品。

## 3. DSH desktop 统一交付层

DSH desktop 不是商品本身，它是统一交付底座。

### 3.1 底座包含什么

- 桌面端主壳
- 证据底座
- 状态管理
- 权限和审计
- 导出能力
- `连接器 / MCP` 接入能力

### 3.2 底座不做什么

- 不把每个能力包塞进主壳
- 不把外部账号、密钥、登录态混进包里
- 不把一次性外部动作默认自动执行

### 3.3 交付方式

每个能力包都通过统一底座交付：

- 同一套桌面体验
- 同一套证据引用
- 同一套草稿/审核/发布状态
- 同一套导出格式
- 同一套日志和审计方式

## 4. 能力包设计

能力包不是功能堆积，而是“回答一类明确问题”的最小单元。

### 4.1 横向能力包

- 深度调研
- 数据分析
- 文档 / 报告生成
- 知识库
- 客服辅助
- 多模态工作台

### 4.2 领域能力包

- 专利
- 招投标
- 具身智能

### 4.3 包内标准输出

每个能力包都应该有：

- 输入说明
- 交付说明
- 证据来源
- 结果状态
- 失败说明
- 示例样本
- 测试样例

## 5. 目录设计

目录设计要同时满足两件事：

1. 有层次
2. 能隔离能力包

### 5.1 推荐顶层结构

```text
project/
  market/
    闲鱼/
      listings/
      titles/
      intros/
      posters/
      faqs/
      pricing/
  desktop/
    dsh/
      core/
      packs/
      registry.md
```

### 5.2 闲鱼目录

`market/闲鱼/` 只放前台包装物料：

```text
market/闲鱼/
  listings/
    deep-research/
    data-analysis/
    document-report/
    multimodal-processing/
  titles/
  intros/
  posters/
  faqs/
  pricing/
```

这里的内容只负责“怎么卖”，不放桌面底座实现细节。

### 5.3 DSH desktop 目录

`desktop/dsh/` 只放统一交付底座和能力包：

```text
desktop/dsh/
  core/
    evidence/
    permissions/
    audit/
    export/
    connectors/
  packs/
    horizontal/
      deep-research/
      data-analysis/
      document-report/
      knowledge-base/
      customer-assist/
      multimodal-workbench/
    vertical/
      patent/
      bidding/
      embodied-intelligence/
  registry.md
```

### 5.4 单个能力包目录

每个包都保持同样的内部骨架：

```text
desktop/dsh/packs/<pack-name>/
  manifest.md
  scope.md
  workflow.md
  inputs/
  outputs/
  prompts/
  adapters/
  schemas/
  samples/
  tests/
  assets/
  release-notes.md
```

### 5.5 隔离规则

- 一个包一个目录
- 一个包一套测试
- 一个包一套样例
- 一个包一套说明
- 公共能力只放在 `core/`
- 包与包之间不直接互相依赖
- 跨包复用只能通过 `core/` 或明确的接口

### 5.6 层次规则

- `market/` 是前台
- `desktop/` 是交付底座
- `packs/` 是能力包
- `core/` 是共用底座
- `horizontal/` 和 `vertical/` 是能力包分组

## 6. 开发顺序

建议按这个顺序推进：

1. 深度调研
2. 数据分析
3. 文档 / 报告生成
4. 知识库
5. 客服辅助
6. 多模态工作台
7. 专利
8. 招投标
9. 具身智能

原因：

- 前三项最容易在闲鱼上讲清楚
- 知识库和客服辅助适合做第二波企业化商品
- 多模态工作台增强桌面端通用性
- 专利、招投标、具身智能适合后续做高客单定制

## 7. 最终判断

这个项目不是“先做一堆能力再找商品名”，而是：

1. 先用闲鱼商品包装把入口做出来
2. 再用 DSH desktop 作为统一交付底座
3. 最后把能力包按层次放进目录里，并保持彼此隔离
